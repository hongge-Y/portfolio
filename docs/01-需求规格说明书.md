# 01 · 需求规格说明书（SRS / PRD V2.0）

## 1. 产品定义

**Portfolio 校园成长平台**：面向高校学生、家长、辅导员/书记的一体化成长服务平台。核心四件事——请假、课表、奖学金评定、家长-学生联动，外围承载校园资讯（新闻/赛事/广告）、成长档案（红黑榜）、站内消息与激励体系（小宠/光粒）。

**不做什么**（范围声明，避免无限膨胀）：
- 不做教务系统本体，课表通过导入/接口从教务获取，只做展示与评价。
- 不做支付、不做对接微信小程序端（V2 之后）。
- 不做学校统一身份认证对接（用本系统账号体系）。

## 2. 角色与权限矩阵

系统共 **7 个角色**，用户可同时具备多角色且带组织作用域（`sys_user_role.org_id`）。

| 编号 | 角色 | 说明 | 判定来源 |
|---|---|---|---|
| R1 | 学生 STUDENT | 基础使用者 | `org_employee_unit.type_id`=学生 |
| R2 | 学委 MONITOR | 班级学生干部 | 学生 + `sys_user_role`=MONITOR(org=班级) |
| R3 | 辅导员 COUNSELOR | 一级审批人 | `org_class.counselor_id` 或 user_role=COUNSELOR |
| R4 | 书记 SECRETARY | 二级审批人 | user_role=SECRETARY（学院级） |
| R5 | 授课老师 TEACHER | 只看被分享的班级请假 | user_role=TEACHER |
| R6 | 家长 PARENT | 关联学生后可见其内容 | user_role=PARENT |
| R7 | 管理员 ADMIN | 后台内容与组织管理 | user_role=ADMIN |

## 4. 关键业务流程与状态机

### 4.1 请假状态机（F-11~F-16）

```
                    ┌──────────────┐
                    │  申请提交     │
                    └──────┬───────┘
         days<=3           │           3<days<=7
      ┌────────────────────┴───────────────────┐
      ▼                                        ▼
 [10 待辅导员审批]                        [10 待辅导员审批]
      │ 批准                                   │ 批准
      ▼                                        ▼
 [20 已通过待销假]  ◄──── 书记批准 ────  [11 待书记审批]
      │                                        │ 驳回
      │ 学生销假(可未到期末日提前销假)          ▼
      ▼                                   [30 已驳回]
 [21 已销假]
      │
      │ 到期后 24h 未销假 → 定时任务
      ▼
 [50 超期未销假] + 双端提醒

 [10/11] 学生可取消 → [40 已取消]
 [30] 学生可取消/修改后重新提交
```

**校验规则（后端强制，前端预校验调用 `GET /leave/rule`）**

| 规则 | 阈值 | 违反时 |
|---|---|---|
| 在途假条数量 | ≤ 3（状态 10/11/20） | 400 `LEAVE_IN_FLIGHT_LIMIT` |
| 时间重叠 | 与本人所有未结束假条不重叠 | 400 `LEAVE_TIME_CONFLICT` |
| 单次天数 | ≤ 7 天 | 400 `LEAVE_TOO_LONG`（提示去一站式） |
| 开始时间 | ≥ 当前时间 - 1h | 400 `LEAVE_TIME_INVALID` |
| 审批人存在 | 班级必须配辅导员 | 400 `LEAVE_NO_COUNSELOR` |
| 附件 | ≤ 5 个，每个 ≤ 10MB | 400 `FILE_LIMIT` |

**修改结束时间**：仅状态 20/21 可改；改后状态回到 10，重建审批节点，历史审批记录保留（新 `leave_approve` 记录 step 递增）。

### 4.2 家长关联状态机（F-18）

```
  PENDING(0) ──同意──► AGREED(1) ──任一方解除──► REMOVED(3)
      │
      └──拒绝──► REJECTED(2)  （申请方可再次申请，唯一键复用同一条记录并重置为 0）
```
- 一个家长可关联多个学生；一个学生可被多个家长关联（`uk_pair` 保证不重复）。
- 申请时对方收到站内消息 + 红点；短信提醒 V2 不做。
- 解除后，家长端历史可见内容保留 7 天只读，之后不可见。

### 4.3 奖学金状态机（F-23）

```
计划: 草稿(0) → 报名中(1) → 评审中(2) → 公示中(3) → 已结束(4)
申请: 10待审 → 20辅导员通过 → 30院系通过 → 40通过 → 60公示 → 70发放
                          └─驳回─► 50已驳回
```
- 计分公式：`total = gpa*10*0.6 + 红榜加分 − 黑榜扣分 + 综合素质分`，规则来自 `sch_plan.rule_json`。
- 排名并列时按 `gpa` 降序、`create_time` 升序。
- 公示期不少于 3 个自然日，公示期内学生可申诉（走消息）。

### 4.4 赛事报名（F-22）
`canRegister` 判定：活动已发布 + 当前时间在 `[start_register_time, end_register_time]` + 用户是该 `visible_org_id` 子树内学生 + 未重复报名。组队人数上限 `group_count`（1=个人赛）。

## 5. 补齐模块的详细需求（原文档完全缺失，本版新增）

### 5.1 课表（F-09）
- 数据来源：教务 Excel 导入（管理员）+ 手工维护；预留教务 API 适配器接口 `TimetableProvider`。
- 展示：周视图 7 列 × 12 节，当前周高亮，点击卡片显示课程详情；支持切换周次。
- 移动端：默认显示 3 天 + 左右滑动。
- 无数据时展示"暂未同步课表，请等待教务导入"，**不允许展示假数据**。

### 5.2 课程评价（F-10）
- 只有本学期有该课程且未被评价的学生可评；每人每课一次，可修改 1 次（24h 内）。
- 三维度：教学水平 / 内容质量 / 课堂氛围，1-5 星；总分=均值×2（10 分制）。
- 匿名：匿名时对教师与管理员均不显示学生信息，仅统计聚合。
- 教师端只看聚合结果，不进入本系统（走管理后台）。

### 5.3 奖学金（F-23）
见 4.3。材料上传 PDF/图片，最多 5 个；审批意见必填于驳回。

### 5.4 提醒机制（F-16）
| 事件 | 通知对象 | 渠道 | 实现 |
|---|---|---|---|
| 学生提交销假 | 辅导员 | 站内消息 | 事件同步 |
| 请假到期超 24h 未销假 | 辅导员 + 学生 | 站内消息 | 定时任务每小时扫 |
| 审批待处理超 24h | 审批人 | 站内消息 | 定时任务 |
| 家长关联申请 | 对方 | 站内消息 + 红点 | 事件同步 |
| 奖学金公示开始 | 计划范围内学生 | 站内消息 | 定时任务 |

### 5.5 可见性规则（原文档只说"见 4.1"，本版明确）
```
内容可见 = 内容.visible_org_id ∈ 用户组织祖先链 ∪ {用户组织子孙}
        ∧ now ∈ [start_time, end_time]
家长用户：用户组织 = 其所有 AGREED 学生组织并集；
         黑榜还需 rank.relative_visible = 1
```
实现：`org_unit.path` 前缀匹配，一次 SQL 完成，禁止循环查库。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 列表接口 P95 < 300ms（1 万数据量）；首页首屏 < 2s（4G） |
| 并发 | 支持 500 在线；请假提交 50 TPS 不超卖（乐观锁 + 唯一约束） |
| 安全 | 密码 BCrypt；传输 HTTPS；RSA 加密登录体；越权校验在每个接口；SQL 参数化；XSS 富文本白名单 |
| 兼容 | Chrome/Edge 最新两版、iOS Safari 15+、微信内置浏览器 |
| 可用 | 单机部署，服务重启 < 30s；数据库每日备份 |
| 可维护 | 接口文档由 springdoc 自动生成，与代码同步 |
| 日志 | 请求 traceId 贯穿；操作日志保留 90 天 |
