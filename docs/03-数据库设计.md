# 03 · 数据库设计

> 建表脚本：同目录 `03a-schema.sql`（可直接执行，含初始化数据）。
> 本文说明**为什么这样设计**、表之间关系、枚举与索引策略，两者必须同步修改。

## 1. 设计原则

| 原则 | 落地 |
|---|---|
| 单一组织表 | 学校/学院/系/班统一存 `org_unit`，用 `type` 区分，`path` 存祖先路径支持子树查询 |
| 扩展信息分表 | `org_college` / `org_class` 只放特有字段，避免宽表 |
| 账号与档案分离 | `sys_user`（登录）↔ `org_employee`（学号/身份证/组织），一个账号对应一个档案 |
| 内容主表 + 正文表 | 列表页不查 `MEDIUMTEXT`，正文单独表，避免回表 |
| 关系表带状态 | 家长关联、赛事报名用状态机列，不硬删 |
| 软删除 | `deleted` 标记，列表查询统一带 `deleted=0`（MyBatis-Plus 全局逻辑删除） |
| 时间统一 DATETIME | 不用时间戳整数，可读、可索引、可时区转换 |
| 金额 DECIMAL | 奖学金金额禁止用 float |

## 2. 表清单（43 张）

### 2.1 账号与权限（5）

| 表 | 说明 | 关键字段 |
|---|---|---|
| `sys_user` | 登录账号 | `account`/`mobile`/`mail` 三选一登录，`password_hash` 可为 NULL（纯验证码用户） |
| `sys_role` | 角色字典（7 条） | `code` |
| `sys_user_role` | 用户角色 + 作用域 | `(user_id, role_code, org_id)` 唯一 |
| `sys_third_account` | 三方绑定 | `(provider, open_id)` 唯一 |
| `sys_login_log` | 登录审计 | — |

### 2.2 组织架构（7）

| 表 | 说明 | 关系 |
|---|---|---|
| `org_unit` | 四级组织树 | `parent_id` 自关联，`path` 形如 `/1/2/3/4/` |
| `org_college` | 学院扩展 | `org_id → org_unit(type=2)` |
| `org_class` | 班级扩展 | `org_id → org_unit(type=4)`，`counselor_id → org_employee` |
| `org_employee_type` | 员工类型 | 学生/学委/教师/辅导员/书记/行政 |
| `org_position` | 职位 | 校长/院长/辅导員/学委… |
| `org_employee` | 员工档案 | `user_id → sys_user`，`(root_org_id, employee_no)` 唯一 |
| `org_employee_unit` | 员工-组织 | 一人可属多组织（如教师兼任班主任） |

> **角色 vs 员工类型**：`employee_type` 是"身份"（学生/教师），`sys_role` 是"权限"（能否审批）。学委 = 员工类型"学委" + 角色 `MONITOR`，两个都要写，前者驱动展示、后者驱动接口鉴权。

### 2.3 家长关联（1）

`rel_relative_link`：`(parent_user_id, employee_id)` 唯一，`status` 0/1/2/3。解除不删记录，便于审计与恢复。

### 2.4 请假（4）

| 表 | 说明 |
|---|---|
| `leave_request` | 主表，`days` 冗余存储（避免每次算），`version` 乐观锁，`overdue_warn` 防重复提醒 |
| `leave_attachment` | 附件 |
| `leave_approve` | 审批节点，按 `step` 顺序生成；改期时**追加**新节点而非覆盖 |
| `leave_share` | 学委分享快照（`snapshot_json`），`share_token` 唯一，`expire_time` 24h |

### 2.5 消息（2）

`msg_notification`（主体，含 HTML 正文）+ `msg_receive`（收件人 × 已读状态）。`(notification_id, to_user_id)` 唯一防重复投递；`to_user_ids` 冗余便于发件箱展示。

### 2.6 内容（12）

`pub_news` / `pub_news_content` / `pub_news_image`；`pub_ad`；`pub_match` / `pub_match_content` / `pub_match_register`；`pub_rank` / `pub_rank_content` / `pub_rank_label`；`pub_like`；`pub_share_link`。

可见性统一用 `visible_org_id`（指向 `org_unit`），`1` 表示全校公开。

### 2.7 教务（3）
`edu_course`、`edu_timetable`（`weeks` 存 `1-8,10-16` 字符串）、`edu_eval`（`(employee_id, course_id, term)` 唯一，一人一课一次）。

### 2.8 奖学金（4）
`sch_plan`（`rule_json` 存计分规则）→ `sch_apply`（含 `total_score`、`rank_no`）→ `sch_approve`（多级）→ `sch_publicity`（公示快照）。

### 2.9 可选（2）
`task_today`、`risk_record`（P2）。

### 2.10 公共（3）
`sys_file`、`sys_dict`、`sys_operation_log`。

## 3. 关系图（文字版）

```

   │                │                                 │
   │                │                                 ├─1 org_class
   │                │                                 └─1 org_college
   │ 1─n sys_user_role
   ├─1─n rel_relative_link n─1 org_employee(学生)
   ├─1─n msg_receive n─1 msg_notification
   └─1─n pub_like

org_employee 1─n leave_request 1─n leave_approve
                               1─n leave_attachment
org_unit(班级) 1─n leave_share
org_employee 1─n edu_timetable?  (经 edu_course.class_org_id)
org_employee 1─n sch_apply n─1 sch_plan 1─n sch_approve
```

## 4. 索引策略

| 场景 | 索引 |
|---|---|
| 登录 | `uk_account` / `uk_mobile` / `uk_mail` |
| 我的请假列表 | `idx_emp_status (employee_id, status)` |
| 学委查班 | `idx_class_status (class_org_id, status)` |
| 待审列表 | `leave_approve.idx_approver (approver_id, status)` |
| 组织子树 | `org_unit.idx_path (path)` — 用 `LIKE '/1/2/%'` 前缀匹配 |
| 内容可见性 | `(status, start_time)` + `(visible_org_id)` |
| 未读数 | `msg_receive.idx_user_read (to_user_id, read_status, deleted)` |
| 点赞去重 | `uk_target_user (target_type, target_id, user_id)` |
| 奖学金排名 | `idx_status (plan_id, status, total_score)` |

**注意**：`total_score` 在 `idx_status` 内为降序使用，MySQL 8 支持降序索引，可写成 `(plan_id, status, total_score DESC)` 若需。

## 5. 关键 SQL 示例（实现参考）

### 5.1 用户上下文（`/auth/me` 一次性组装）

```sql
SELECT u.id userId, u.account, u.show_name, u.avatar, u.guide_done, u.pet,
       e.id employeeId, e.employee_no, e.name, e.root_org_id, o.path org_path,
       (SELECT ou.org_id FROM org_employee_unit ou
         WHERE ou.employee_id = e.id AND ou.type_id IN (1,2) LIMIT 1) class_org_id
FROM sys_user u
LEFT JOIN org_employee e ON e.user_id = u.id AND e.deleted = 0
LEFT JOIN org_unit o ON o.id = e.root_org_id
WHERE u.id = #{userId} AND u.deleted = 0;
```

### 5.2 家长可见的学生组织

```sql
SELECT e.id employeeId, e.name, ou.org_id classOrgId
FROM rel_relative_link r
JOIN org_employee e ON e.id = r.employee_id
LEFT JOIN org_employee_unit ou
       ON ou.employee_id = e.id AND ou.type_id IN (1,2)
WHERE r.parent_user_id = #{userId} AND r.status = 1;
```

### 5.3 请假在途数校验

```sql
SELECT COUNT(*) FROM leave_request
WHERE employee_id = #{employeeId} AND deleted = 0
  AND status IN (10, 11, 20)
  AND id <> COALESCE(#{id}, 0);
-- > 3 则抛 LEAVE_IN_FLIGHT_LIMIT
```

### 5.4 时间重叠校验

```sql
SELECT COUNT(*) FROM leave_request
WHERE employee_id = #{employeeId} AND deleted = 0
  AND status NOT IN (30, 40) AND id <> COALESCE(#{id}, 0)
  AND start_time < #{endTime} AND end_time > #{startTime};
-- > 0 则抛 LEAVE_TIME_CONFLICT
```

### 5.5 超期未销假扫描

```sql
SELECT id, employee_id FROM leave_request
WHERE status = 20 AND overdue_warn = 0
  AND DATE_ADD(end_time, INTERVAL 24 HOUR) < NOW()
LIMIT 500;
```

### 5.6 广告/新闻前台可见性

```sql
SELECT a.* FROM pub_ad a
WHERE a.deleted = 0 AND a.status = 1
  AND NOW() BETWEEN a.start_time AND a.end_time
  AND (a.visible_org_id IN (:ancestorIds) OR :orgPath LIKE CONCAT('%/', a.visible_org_id, '/%'))
ORDER BY a.sort ASC, a.id DESC;
```

### 6.4 迁移规范
- 表结构变更一律新增 `V{n}__{desc}.sql`，不手改现有脚本。
- 加字段必须可空或有默认值，禁止在千万级表上直接 `MODIFY` 大字段。
- 生产执行前先在测试库 `EXPLAIN` 关键查询。
