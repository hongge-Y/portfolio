# 缺陷记录说明

## 字段约定

每条缺陷必填：**标题 / 模块 / 严重程度 / 发现方式 / 前置 / 复现步骤 / 预期 / 实际 / 根因（代码位置）/ 修法 / 回归手段 / 状态**。

缺"根因"和"回归手段"的条目一律不进这个目录——写不出根因说明还没定位清楚，写不出回归手段说明下次还会坏。

## 严重程度

| 级别 | 定义 | 本项目里的例子 |
|---|---|---|
| P0 | 数据泄露 / 核心流程不可用 / 资金或隐私受损 | BUG-003、BUG-004（跨院看到别院学生的请假理由与奖学金材料） |
| P1 | 主要功能对某类角色失效，或给出错误结论 | BUG-001（书记一条看不到）、BUG-002（管理员 403）、BUG-005（AI 被诱导后给"同意"） |
| P2 | 特定操作路径下的功能/展示异常，有绕行方案 | BUG-007、BUG-008 |
| P3 | 体验与文案问题，不影响业务结果 | BUG-006 |
