# 05 · 参数校验与异常分支（EXC）

统一契约（`docs/04-接口规范.md` §1.1）：HTTP 恒为 200，业务结果看 `code`（200/400/401/403/404/429/500），`message` 可直接展示；业务子码作 `message` 前缀，供前端分支。**所以本项目的用例预期一律写 `code`，不写 HTTP 状态码。**

| 编号 | 前置 | 步骤 | 预期 | 依据 | 状态 |
|---|---|---|---|---|---|
| TC-EXC-01 | 学生 | `GET /leave/{id}`，`id` 不存在（如 999999） | `code=404`，`message`「请假记录不存在」 | E9 / code: `LeaveService#approve` 前置查询 | 已设计 |
| TC-EXC-02 | 辅导员 | `POST /leave/approve {result:3}` | `code=400`「审批结果只能是 1(批准) 或 2(驳回)」 | E11 | 已设计 |
| TC-EXC-03 | 学生 | `POST /leave/apply` 缺 `startTime` | `code=400`，不落库（`leave_request` 无新行） | E2 / DTO 校验 | 已设计 |
| TC-EXC-04 | 学生 | `POST /leave/apply`，`endTime` 早于 `startTime` | `code=400`「结束时间必须晚于开始时间」 | E2 | 脚本覆盖（推论见下） |
| TC-EXC-05 | 学生 | `POST /leave/personal/search {pageNum:0}` | 归一化为第 1 页（`Math.max(pageNum,1)`），返回 `pageNum=1` | E6 / code: `LeaveService` 分页钳制 | 已设计 |
| TC-EXC-06 | 学生 | `{pageSize:0}` / `{pageSize:500}` | 分别钳到 1 / 100，返回体里 `pageSize` 回显的是**钳制后**的值 | E6 / code: `Math.min(Math.max(pageSize,1),100)` | 已设计 |
| TC-EXC-07 | 学生 | `{pageNum:9999}` | 返回空 `list`，`total` 与第 1 页一致（不是 0） | E6 | 已设计 |
| TC-EXC-08 | 学生 | 请假超过 7 天 | `code=400 LEAVE_TOO_LONG`，`message` 含"超过 7 天" | F-11 | 脚本覆盖 |
| TC-EXC-09 | 学生 | 与已有假条时间重叠 | `code=400 LEAVE_TIME_CONFLICT` | F-11 | 脚本覆盖 |
| TC-EXC-10 | 无任何角色 token | 任意 `/api/v1/**` 接口 | `code=401`，`message` 可展示，前端清 token 跳登录 | A11 | 脚本覆盖 |

| TC-EXC-12 | 任意登录用户 | 用 GET 调 `POST` 接口 / 用 PUT 调 `GET` 接口 | 返回 405 或统一错误包（确认口径后写死预期） | §1.1 | 已设计 |

## 说明

- TC-EXC-04 标"脚本覆盖"是因为 `smoke-leave.sh` 里覆盖了 7 天与重叠两条主规则；**"结束早于开始"这条严格说没有独立断言**，跑的时候一起确认，确认不了就降级为"已设计"。这种"用例状态和脚本断言不完全一一对应"的情况必须标出来，不能含糊。
- TC-EXC-12 的预期暂时留空是故意的：Spring 的 405/415 默认返回体不走项目的 `Result` 包装，得先跑一次看真实返回，再决定这个"不统一"要不要记成缺陷（属于**接口一致性**问题，不是功能 bug）。
- 分页钳制这两个上限（`pageNum≥1`、`1≤pageSize≤100`）是读代码确认的边界值，**测边界值最容易出成绩**：0 / 1 / 100 / 101 四个点各跑一次，比测 20 个正常值有用。
