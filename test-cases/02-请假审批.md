# 02 · 请假与分级审批（LEAVE）

状态机（`docs/01-需求规格说明书.md` §4.1）：

```
申请 → [10 待辅导员]
          ├─ days≤3 ─ 辅导员批准 ─→ [20 已通过待销假] ─ 销假 → [21 已销假] ─ 到期 24h 未销假 → [50 超期未销假]
          └─ 3<days≤7 ─ 辅导员批准 ─→ [11 待书记] ─ 批准 ─→ [20]
                                   └─ 驳回 ─→ [30 已驳回] ─ 学生可取消/修改后重提
[10/11] 学生可取消 → [40 已取消]
```

## 设计这些用例时踩到的坑（面试可直接讲）

1. **在途上限与时间重叠会互相干扰**：脚本造数据时如果写死时间，会被上一轮的残留单判成"时间重叠"，脚本自己造不出基线——所以 `test-permissions.sh` 里时间段是随机的，`reset-demo.sh` 默认只预演、加 `--apply` 才真清。
2. **越级审批的拒绝点不在状态判断上**：`approve()` 是「先判状态 ∈{10,11} → 再取当前待审节点 → 再比对 `approver_id` 与登录态 `employeeId`」，所以书记去审一张刚提交的单，返回的是 **403「当前待审批人不是你」**，不是 400。写用例时预期写错这一条，回归就会假失败/假通过。
3. **"通过"和"驳回"走的不是同一条写库路径**：通过要算 `MIN(step)` 判断是否还有下一级（`next==null` 才是 20，否则 11 并通知下一级审批人）；驳回直接把状态打 30 并要求原因。两条分支的状态集合不同，用例必须各测一遍，别只测通过。
4. **申请 id 不能写死在脚本里**：冒烟脚本会清理自己造的申请，写死必然 404。
