# 测试用例索引与覆盖矩阵

本目录是按业务模块拆开的用例清单。用例不是凭想象写的，每条都挂了一个可查的**依据**：

| 依据类型 | 含义 | 例子 |
|---|---|---|
| `F-xx` | 需求规格说明书的功能编号 | `F-11` 请假申请（≤3 在途、不重叠、>7 天拦截） |
| `Exx` / `A1` | `docs/04-接口规范.md` 的接口编号 | `E11` 请假审批 |
| `code:` | 代码位置（写清类与方法） | `code: LeaveService#apply` |
| `脚本:` | 已在 `scripts/` 有对应断言 | `脚本: smoke-leave.sh` |

## 列含义

| 列 | 说明 |
|---|---|
| 编号 | `TC-<模块>-<序号>`，模块缩写见下表 |
| 前置 | 需要哪些账号与数据 |
| 步骤 | 被测动作，等价于你在 Postman / 页面上点的那几步 |
| 预期 | 可判定的结果：状态码、业务子码、字段、状态值 |
| 状态 | `脚本覆盖` = `scripts/` 里有对应断言，可复跑；`已设计` = 用例已写但还没跑，跑完改成 `通过/失败` |

> **重要口径**：`脚本覆盖` 只代表这条检查在脚本里存在且可执行，**不代表我宣称它在他机器上已跑通**。真实执行记录以 `TESTING.md` §6 为准，跑一次填一次。
> 状态不是"全部通过"的用例表是可信的；一份全绿但没有任何复跑命令的用例表，面试时最容易被问穿。

## 覆盖维度（不只是"功能点走一遍"）

1. **角色 × 资源矩阵**：7 类角色 × 请假/奖学金/后台统计/家长关联，正例与 403 反例成对出现。
2. **行级数据范围**：本班（精确匹配 `class_org_id`）、本学院（`orgPath` 前缀）、全校（`/`）、家长（已绑定孩子）四档，每档都配"越界应被拒"的反例。
3. **状态机**：请假 `10 → 11 → 20 → 21`（含 `30 已驳回`、`40 已取消`、`50 超期未销假`）与奖学金 `10 → 20 → 30 → 40 → 60 → 70`，重点测**非法跃迁**（越级审批、重复审批、已通过再取消）。
4. **字段脱敏**：学委看本班请假时 `reason` / `attachments` 不返回（不是返回空串）；家长黑榜受 `relative_visible` 控制。
5. **边界与异常**：3/4 条在途、7/8 天、时间重叠、开始时间早于当前 1h、分页 size=0 与超大页码、id 不存在、未登录、过期 token。

## 怎么执行

```bash
# 前置：后端已启动（默认 http://localhost:8080），演示数据已导入
bash scripts/check-env.sh          # 环境自检：端口、依赖、库连通
bash scripts/smoke-leave.sh        # 请假闭环
bash scripts/smoke-scholarship.sh  # 奖学金四级流转
bash scripts/smoke-content.sh      # 内容可见性 + 消息
bash scripts/smoke-relative.sh     # 家长关联 + 课表
bash scripts/test-permissions.sh   # 角色与行级权限回归（自造基线、跑完自清）
```

每个脚本都会打印 `✅ 通过 / ❌ 失败（实际：xxx）` 并在结尾汇总计数；失败时把那行贴进 `bug-reports/`。
